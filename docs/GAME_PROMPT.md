# 《夢幻西餐廳》復刻 — 遊戲生成提示詞 (GAME PROMPT)

> 本文件即為「遊戲提示詞」。把它整份貼給任何具備程式實作能力的 AI Agent，
> 即可產出一款高度還原 1998 年華藝國際《夢幻西餐廳》系列（尤以《決戰全台灣》為藍本）
> 玩法的餐廳經營模擬遊戲。本文件同時是本專案的規格來源與驗收依據。

## 0. 角色與任務（Prompt 主體）

你是一位專精「16-bit 時代經營模擬遊戲」的資深遊戲程式設計師與系統設計師。
你的任務是**復刻 1998 年台灣華藝國際代理發行的《夢幻西餐廳》（Bistro / Restaurant Dream）系列**，
並以《夢幻西餐廳：決戰全台灣》為主要藍本 —— 也就是把舞台放在台灣各地夜市與商圈的那個版本。

要求：

1. **玩法高度還原**：精神、系統、數值手感、UI 版面配置與操作流程都要對得上原作，不是做一款「類似的餐廳遊戲」。
2. **美術原創**：不得使用原作任何圖像、音樂、字型或商標。改用**自行以程式繪製的像素圖**重現當年 VGA/16-bit 的視覺語言。
3. **名稱原創**：原作員工角色是以當年台灣藝人諧音梗命名，復刻時請沿用「諧音梗」的趣味，但使用**自創的假名**，不得使用真實藝人姓名或肖像。
4. 產出必須**可直接執行、可完整破關**（從一星小店玩到五星＋年度大獎），不是技術 Demo。

的原作事實，復刻時須逐項對應：

| 項目 | 原作設定 |

| 系列前身 | 日版一代起點為「木場」，其後為銀座、渋谷、六本木；黃金版／二代《挑戰全世界》改為各國城市 |

| 桌椅動線 | 服務生動線與廚房距離是主要難點。**離廚房越遠的服務生負責桌數越少**、客人等太久會生氣離開 |

## 2. 核心玩法循環（Core Loop）

```
開店前        營業中（即時模擬）                 打烊後
──────       ──────────────────────           ──────
排桌椅    →   客人上門 → 帶位 → 點餐 →        →  日結算（營收/成本/來客/抱怨）
備貨進料      廚師料理 → 服務生送餐 → 用餐 →      週日：雜誌排名 + 星級評定
編菜單        結帳 → 收桌 → 翻桌率                  週一：社區獎金
排班/時薪         ↑ 同時進行：天氣、突發事件、          
調空調                  設備故障、清潔度、          
               顧客滿意度即時累積 → 評價分數        
```

一句話：**用有限的錢，在對的地點、對的菜單、對的動線與對的人手下，把翻桌率與滿意度推到五星。**

## 3. 系統規格明細

### 3.1 時間系統
- 1 真實秒 = 1 遊戲分鐘（提供 1x / 2x / 4x / 暫停）。
- 營業日 = 00:00–24:00，玩家設定 `openHour` / `closeHour`（如 10:00–23:00）。
- 打烊後仍有客人未離場時，需等清場才結算（可選「打烊趕人」導致評價下降）。
- 每 7 天（週日 22:00）觸發週結算；每週一 00:00 發社區獎金。

### 3.2 餐廳平面編輯器（Build Mode）
- 網格制：**20 × 13 格等角（isometric）菱形網格**，每格 42×21 px（邏輯畫布 960×600，以整數倍放大）。
- 固定元素：外牆、大門（客流入口）、**廚房出餐口（pass）**、廁所、櫃台。
- 可放置傢俱：各式桌子（2/4/6 人）、椅子、櫃台、盆栽、畫作、地毯、燈具、音響、監視器、滅火器、紅外線、保全主機、垃圾桶等。
- 每件傢俱有：尺寸、價格、**裝潢分數（風格相符度）**、阻擋格、可坐人數。
- 保鏢式限制：
  - 桌椅必須「相鄰且可達」，否則為無效座位（UI 以紅框標示）。
  - 大門到座位、座位到廚房出餐口必須存在**可通行路徑**（A* 驗證）。
  - 保留走道寬度不足會造成服務生互卡、上餐變慢。
- 搬遷到新地點時：**格局、坪數、街景皆不同，且裝潢全部清空重排**（保留原作痛點）。

### 3.3 菜單編輯器（Menu）
每道菜資料結構：

```js
{
  id, name, category,          // staple 主食 / side 小菜 / soup 湯 / drink 飲料 / alcohol 酒 / dessert 甜點
  baseCost,                    // 基準材料成本
  ingredientGrade,             // 材料等級 0–100（越高成本越高、越好吃）
  taste,                       // 味道濃淡 0–100（50 為中間值）
  portion,                     // 份量 0–100（影響飽足與成本）
  cookTime,                    // 調理時間 1–60 分鐘（過短會扣評價）
  price,                       // 售價（玩家自訂）
  unlockedStars,               // 需要幾星解鎖
  tags,                        // 辣 / 清淡 / 甜 / 冰 / 在地 / 觀光客愛 等
  popularityByLocation         // 各地點的受歡迎度係數
}
```

規則：
- 同時上架上限（一星 8 道 → 五星全部），避免「一道菜打天下」失去樂趣（原作前期可只賣蛋包飯，故上限不宜過嚴）。
- 可進貨的**份數庫存**獨立計算；賣完＝客人點不到餐（重扣評價）。
- 每項設定即時反映在「顧客期待值」：好吃度、份量滿足、價格划算度、等待時間。
- 調理時間與售價呈正相關手感：便宜又 3 分鐘上菜 = 客人覺得是微波食品，評價暴跌。

### 3.4 庫存與進貨
- 每道菜有 `stock`（份）。營業中可隨時叫貨（外送延遲 30 分鐘到貨）。
- 生鮮類隔日折損（10%），飲料酒類不折損。
- 進貨價受**季節／事件／通膨**影響（±30%）。

### 3.5 員工系統
- 職種：**廚師**（料理速度、廚藝＝好吃度加成）、**服務生**（移動速度、服務態度、可指派職務）。
- 屬性：姓名（諧音梗）、頭像、年齡、`speed`（移動）、`skill`（廚藝／服務）、`stamina`（疲勞）、`wage`（時薪）、`specialty`（擅長菜系）、隱藏個性。
- 服務生職務指派：帶位、點餐、送餐、收桌、**清掃廁所**、清掃店內、站櫃台結帳、外場巡視。
- **排班制**：設定每位員工的上下班時段；人手不足會直接反應在等待時間。
- 疲勞：連續上班 > 8 小時效率下降、心情變差，可能**請假或離職**；調薪可留人。
- 服務生負責桌數依「與廚房出餐口的距離」動態分配，靠近廚房者可多帶桌（原作核心難點）。

### 3.6 顧客 AI（有限狀態機）
```
ARRIVING → QUEUEING（候位） → ESCORTED（帶位中） → SEATED
  → ORDERING → WAITING_FOOD → EATING → PAYING → LEAVING
                          ↘ ANGRY_LEAVE（等太久／沒菜／沒位子／太冷太熱／太髒）
```
- 每位顧客有：`patience`（耐心秒數）、`budget`、`preferTags`、`hunger`、`mood`（滿意度 −100~+100）、`type`（學生 / 上班族 / 家庭 / 觀光客 / 美食評論家 / VIP）。
- 心情扣分來源：候位過久、帶位太慢、上餐太慢、菜難吃、份量太少、太貴、環境太冷太熱、廁所髒、隔壁桌太吵、服務生態度差。
- 心情加分來源：上餐快、好吃、份量足、價格實惠、裝潢漂亮、音樂好聽、服務生態度好、被招待。
- 結帳金額 = 售價 ×（顧客類型加成）×（心情溢價）；心情極差會**不付錢就走**或**給負評**。
- 顧客離場時把 `mood` 灌入聲望累積器（分為**社區**與**區外**兩桶分開計算）。

### 3.7 評價與星級
- 兩個獨立分數桶：`communityRating`（社區）、`outsideRating`（區外），初始皆約 350（0–500）。
- 每次顧客結帳：`桶 += (mood / 100) * k`，`k` 依顧客類型（評論家權重 ×5、觀光客計入區外桶）。
- 名氣 `fame`（0–100）影響來客數與顧客類型組成。
- 星級門檻（兩桶都必須達標，並滿足營業天數／週排名）：

| 星級 | 社區評價 | 區外評價 | 額外條件 | 解鎖 |
|---|---|---|---|---|
| ★1 | 350 | 350 | 開業 | 中壢新明夜市、8 道菜 |
| ★2 | 380 | 360 | 營業滿 7 天 | 基隆廟口、菜單 +6 |
| ★3 | 410 | 385 | 週排名進前 8 | 台北南陽街、菜單 +8 |
| ★4 | 435 | 410 | 週排名進前 3，且曾拿第一 | 台中中華路／台南東帝士、全菜單解鎖 |
| ★5 | 460 | 435 | 連兩週雜誌第一＋評價 460/435 | 高雄新堀江 |
| 年度大獎 | — | — | 五星後再撐滿一年且年度評比第一 | 兩道隱藏歌名料理 |

- **換地點會使區外評價大幅下滑**（原作實測現象），需靠重新經營爬回。
- 若連續 3 週評價低於門檻會**掉星**（給壓力，但不至於 GG）。

### 3.8 雜誌週排名（每週日 22:00）
- 五個榜：**口味、服務、裝潢、價格、人氣**，各取 1–20 名。
- 每項分數由本週統計算出（平均等待時間、抱怨次數、裝潢總分、平均客單價 vs 同業、來客數）。
- 總榜（總合名次）決定知名度成長與升星條件。
- 排名提升 → `fame` 上升 → 來客數上升（正回饋，這是原作爽感來源）。

### 3.9 地點（Location）
| 地點 | 星級需求 | 租金/日 | 基礎客流 | 顧客組成 | 口味偏好 | 格局特性 |
|---|---|---|---|---|---|---|
| 中壢新明夜市 | ★1 | 低 | 中 | 學生、家庭 | 重口味、便宜大碗、炸物 | 小坪數、夜市街景 |
| 基隆廟口 | ★2 | 中 | 高 | 觀光客、家庭 | 海鮮、湯品、小吃 | 港口海景、雨天多 |
| 台北南陽街 | ★3 | 高 | 很高 | 上班族、學生 | 快速、套餐、咖啡 | 補習街、中午尖峰 |
| 台中中華路 | ★4 | 中高 | 高 | 夜市客、情侶 | 甜、炸、飲料 | 夜市大道 |
| 台南東帝士廣場 | ★4 | 中 | 中高 | 家庭、觀光客 | 甜、在地小吃 | 百貨商圈、大坪數 |
| 高雄新堀江 | ★5 | 最高 | 最高 | 年輕人、情侶 | 流行、飲料、異國 | 商圈、大坪數、時尚裝潢加分 |

- 每地點：街景、色調、天氣分布、路人數、租金、裝潢風格相符度權重皆不同。
- 搬遷費用 + 押金；搬遷後裝潢需重買（可折舊退 30%）。

### 3.10 天氣與環境
- 每日天氣：晴 / 陰 / 雨 / 豪雨 / 寒流 / 熱浪（依地點季節機率）。
- 效果：客流倍率 0.5–1.25；雨天外送進貨延遲；寒流提高熱湯／酒類需求，熱浪提高飲料／冰品需求。
- 空調：玩家設定 16–30℃，顧客舒適帶為 22–26℃（依當日天氣偏移）；偏離會累積煩躁。
- 音樂：可選曲風（慵懶 / 南國風 / 古典一 / 古典二 / 流行），契合顧客組成可加分。
- 清潔：地板髒污度、廁所髒污度；需指派服務生清掃，太髒重扣評價。

### 3.11 突發事件（每日 1–3 件）
- **正面**：電視採訪（知名度暴增）、美食評論家突擊、名人來訪、社區活動補助、隔壁店家倒閉帶來人流。
- **負面**：設備損壞（爐具／冷氣／冰箱）、停電、食材漲價、老鼠出沒、宵小竊盜、員工請假／離職、客人食物中毒（食材等級過低時機率上升）、奧客鬧場。
- 防治設備：監視器、紅外線防盜、消防設備、保全主機 —— 買了對應事件損失大幅下降（原作要全買）。

### 3.12 財務
- 收入：餐費、酒水、社區獎金（每週一約 20 萬）、活動補助。
- 支出：進貨、**時薪 × 工時**、租金（每日）、水電（依空調與燈具）、維修、設備、裝潢、搬遷。
- 現金為負超過 7 天 → 破產結局（可讀檔）。
- 提供「日報表／週報表／月報表」與歷史折線圖。

### 3.13 存讀檔
- 手動存檔 5 個槽位 + **每日自動存檔**（原作易閃退，復刻需內建自動存檔，這是體貼也是還原）。
- 存檔含：日期、地點、現金、評價兩桶、星級、菜單、庫存、員工、裝潢格線、統計歷史。

## 4. 數值公式（請照實作，手感才會對）

```
客流速率（人/遊戲分鐘）
  = 地點基礎客流
  × 天氣倍率
  × 時段倍率（早餐 0.4 / 午餐 1.6 / 下午 0.8 / 晚餐 1.8 / 宵夜 0.9）
  × (0.4 + fame/100 * 1.2)
  × 裝潢吸引係數 (0.85 ~ 1.25)
  × 菜單契合度（該地點偏好 tag 的平均匹配）
  × 價格合理性（同類菜平均價 vs 當地期望價）
  × (0.7 + 星級 * 0.1)
  ＋ 玩家拉客加成（每次點路人 +0.5%，上限 +30%，半衰期 20 分鐘）

好吃度 dishScore ∈ [0,100]
  = 廚師廚藝 * 0.4 + 材料等級 * 0.35 + 味道濃淡契合度（顧客偏好 vs taste）* 0.15
  + 調理時間合理性 * 0.10
  調理時間合理性：過短（< 8 分）嚴重懲罰、8–15 分輕懲罰、20–40 分最佳、> 45 分開始扣（客人等太久）

價格划算度 valueScore = clamp(期望價 / 售價, 0, 1.4)

顧客心情變化（每秒）
  mood += Σ(正向項) − Σ(負向項)
  上餐等待：每超過 patience 的 25% → −0.8/s
  環境溫度偏離 1℃ → −0.15/s（乘上顧客敏感度）
  廁所髒污 > 60 → −0.3/s；地板髒污 > 70 → −0.2/s

翻桌率 = 1 / (帶位 + 點餐 + 等餐 + 用餐 + 結帳 + 收桌)
  → 動線設計與人手配置直接影響賺錢效率

服務生負責桌數上限 = clamp(round(6 * (1 - normalizeDistance(座位, 出餐口))), 1, 6)
```

## 5. 美術與音效風格（復刻當年視覺語言）

- **解析度**：邏輯畫布 960×600（VGA 16-bit 感、保留受限調色盤與網點抖動），整數倍放大，`image-rendering: pixelated`。
- **色盤**：以當年 8-bit 調色盤為準，限制色數、避免現代漸層與陰影。
- **UI**：Win95 時代米黃色對話框、深藍標題列、3D 凸起／凹陷邊框、點陣字型感；面板一律為可拖曳視窗，並有右上角 X。
- **平面圖**：斜 45° 俯視（等角透視）；人物為 24×36 像素、4 方向、4 格走路動畫，另有端盤／就座／用餐／生氣等姿勢。
- **光線**：畫面上要有一層打光 —— 時段色調（晨／午／昏／夜）、燈具在地板上的暖色光池、夜間霓虹溢光、人物接觸陰影、廚房蒸氣與爐火閃動，全部用網點抖動繪製，不使用漸層。
- **街景**：每家店窗外有對應地點的像素街景（夜市燈籠、港口貨櫃、補習街招牌、百貨霓虹）。
- **音效**：以 WebAudio 程序化合成（不需外部檔案）——開門鈴聲、點餐、上菜、收銀、抱怨、週結算「叮」、升星小號。
- **BGM**：程序化 MIDI 風循環，提供 4–5 種曲風供選擇，不同曲風對顧客組成有加成。
- **文字**：繁體中文，用語台灣化（「來客數」「翻桌率」「奧客」「小費」）。

## 6. UI / UX 流程

主畫面（餐廳即時視圖）底部為工具列，開啟各管理視窗：

```
[ 菜單 ] [ 進貨 ] [ 員工 ] [ 排班 ] [ 裝潢 ] [ 設備 ] [ 空調 ] [ 音樂 ] [ 報表 ] [ 雜誌 ] [ 存檔 ] [ 搬遷 ]
                                                    右上：時間 / 天氣 / 現金 / 星級 / 評價雙桶
```

- **開店前**：強制進入 Build Mode 佈置，按「開始營業」才放人。
- **營業中**：可即時調整售價、叫貨、調空調、指派清掃、點路人拉客，但改動裝潢需先打烊。
- **提示系統**：左下角「餐廳小提示」滾動顯示即時問題（太冷／太熱／有人在等／廁所髒／庫存不足）。原作有此提示，務必實作。
- **每週日 22:00**：全螢幕結算窗，秀出五榜名次、星級進度條、財務摘要。
- **升星／年度大獎**：全螢幕慶祝動畫 + 獎盃 + 隱藏料理解鎖通知。
- **教學**：第一次開店用對話框教「擺桌 → 編菜單 → 進貨 → 開店」，語氣要像 90 年代手冊。

## 7. 技術要求

- **零外部依賴**：純 HTML + CSS + ES Modules 原生 JS，不使用任何框架／CDN／build step。
- **渲染**：餐廳平面用 `<canvas>`（像素完美），管理面板用 DOM（利於排版與輸入）。
- **模擬與渲染分離**：`sim/` 為純函式 + 可注入亂數（`rng`），必須能在無 DOM 的 Node 環境跑測試。
- **決定性**：同 seed + 同輸入 → 同結果（方便除錯與存檔）。
- **效能**：同時 40+ 顧客、10+ 員工、200+ 傢俱仍需 60 FPS；路徑用 A* 並快取。
- **存檔**：`localStorage`，JSON，含版本號與遷移函式。
- **可測試**：提供 `npm test` 級別的無 DOM 模擬煙霧測試（跑滿 7 天，檢查不變式：現金不為 NaN、評價在 0–500、顧客不卡死）。
