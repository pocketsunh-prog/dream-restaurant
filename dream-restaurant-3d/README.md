# 夢幻西餐廳 3D ─ 日本編 / Dream Restaurant 3D

以 **three.js** 重製的《夢幻西餐廳》3D 版本，舞台移到**日本**，收錄 **28 個日本知名商圈／溫泉地／市場**，
日式風格餐廳（土壁、木地板、榻榻米座敷、障子、暖簾、提燈、行燈、招財貓、酒樽…），
PBR 材質 + 即時陰影 + ACES 色調映射 + 日夜循環。

本專案與 2D 版（上層目錄）**完全分離**，可獨立執行。

---

## 快速開始

```bash
cd dream-restaurant-3d

# 方式 A：用本專案附的伺服器（預設 8081）
node tools/serve.mjs
# → 瀏覽器開 http://127.0.0.1:8081/

# 方式 B：用上層 2D 專案的伺服器（8080）
cd .. && node tools/serve.mjs
# → 瀏覽器開 http://127.0.0.1:8080/dream-restaurant-3d/
```

> ⚠️ 一定要用 HTTP 伺服器開啟，不能用 `file://` 直接開檔：本專案用 ES module
> 與 import map（`three` → `vendor/three.module.js`），`file://` 會被 CORS 擋下。

**離線可用**：three.js（r160）已經放在 `vendor/`，執行時不需要任何網路連線。

## 音訊（程序化合成，無任何音檔）

全部的音樂與音效都是**即時用 Web Audio 合成**，專案裡沒有任何 `.mp3` / `.wav`。

- **BGM**：以日本音階隨機漫步產生旋律（箏／koto 撥弦：三角波＋兩個泛音），
  加上尺八風的氣息長音（兩支微失諧正弦＋帶通噪音）與太鼓脈動（低頻下滑音＋低通噪音）。
  - 音階：`yo`（陽音階，明亮）／`in`・`miyako`（陰音階・都節，物悲）／`minyo`（民謠）／`ryo`（呂）
  - **依立地類型選音階**：繁華街→陽音階、高級地段→陰音階、溫泉・古街→都節、市場→民謠
  - **依晝夜與時段改變**：夜晚速度放慢、音更疏、太鼓更輕；午間尖峰速度加快、音更密
- **SFX（14 種）**：`door` 引き戸＋門口鈴、`seat` 入座、`order` 點餐、`serve` 上菜、
  `eat` 餐具、`pay` 收銀＋零錢、`angry` 不滿低鳴、`happy` 滿意三音、`settle` 打烊鈴、
  `starup` 升級、`error`、`clink` 杯盤、`whoosh` 搬遷、`click` 按鈕
- **環境音**：店內人聲（帶通噪音，隨在店人數變化）、廚房聲（隨使用中的桌數）、雨聲（下雨時）
- **混音**：master → DynamicsCompressor → 輸出；music／sfx／ambience 三條匯流排可各自調音量；
  同一音效 40ms 內不重複觸發，避免大量顧客同時進店造成破音。

模擬層只負責產生事件（`door` / `seat` / `order` / `serve` / `pay` / `angry`），
呈現層用 `drainEvents(state)` 取用並決定要播什麼，兩邊完全解耦。

## 玩法

### 員工與服務流程（核心）

餐廳的營運是一條**任務驅動**的產線：模擬層只產生「任務」，員工自己認領並走過去執行。

```
客人進店 ──有位子──▶ 保留桌位 ──▶【服務生：帶位 seat】──▶ 入座 ──▶ 點餐
   │                                      │
   └──沒位子──▶ 店外排隊（等太久生气離開）  ▼
                                  【廚師：調理 cook】──▶ 菜放上出餐口（畫面上會出現碗盤）
                                            │
                                            ▼
                                  【服務生：配膳 deliver】──▶ 客人開始用餐
                                            │
                                            ▼
                                  用餐結束 ─▶【服務生：お会計 collect】──▶ 結帳、桌面變髒（出現碗盤堆）
                                            │
                                            ▼
                                  【服務生：片付け cleanTable】──▶ 桌子可再帶客
                                  洗手間髒了 ─▶【服務生：トイレ清掃 cleanRestroom】
```

| 任務 | 角色 | 內容 |
|---|---|---|
| `seat` ご案内 | ホール | 到門口把客人帶到桌位（客人會跟著走到座位） |
| `cook` 調理 | 料理人 | 走到爐台煮菜，煮好**把菜放上出餐口** |
| `deliver` 配膳 | ホール | 到出餐口**取菜**（畫面上會端著盤子）再送到桌邊 |
| `collect` お会計 | ホール | 客人用完餐後到桌邊**埋單**（手藝好的服務生小費較高） |
| `cleanTable` 片付け | ホール | 收拾桌面，桌子才能再帶客 |
| `cleanRestroom` トイレ清掃 | ホール | 洗手間髒污過高時自動產生 |

- 任務有**優先度**（埋單 92 ＞ 送菜 86 ＞ 帶位 78 ＞ 收拾 58 ＞ 掃廁所 46），員工挑最要緊的先做。
- 作業時間與走路速度取決於員工的 **skill／speed**，**疲勞**會拖慢一切。
- **人手不足的後果**：沒有料理人 → 客人等不到菜；沒有ホール → 客人等不到帶位／送菜／埋單，
  撐過耐心值就生气離開（評價下降）。客人也可能自己跑去櫃台結帳，但小費減半。
- 員工上限 10 人，至少要留 1 位料理人與 1 位ホール。

### 員工招聘（32 人名冊）

「従業員」面板有三個分頁：

1. **現有員工**：姓名／年齡／時給／擔當／**現在正在做什麼**（待機・ご案内・配膳…）＋
   速度・手腕・体力・疲労四條能力條＋特質標籤，可解雇（資遣費＝時給 ×4）。
2. **招募**：依星級出現的應徵者（★1 8 人／★2 8 人／★3 7 人／★4 5 人／★5 4 人），
   有簽約金（＝時給 ×2）、能力、專長（料理人 10 種料理類別／ホール 5 種服務專長）與 12 種個性；
   雇用後立刻上工（會出現在店裡）。
3. **設備・事件**：購買設備、修理故障設備、查看進行中事件與事件紀錄。

### 事件（34 種）

營業中每 90～210 分鐘擲一次隨機事件（好 12／壞 16／中性 6），
會依**星級、天氣、立地類型**篩選，效果可持續數十分鐘，進行中的事件顯示在畫面右上角：

- **好**：テレビ取材、有名ブロガー来店、SNSでバズる、忘年会の予約、桜まつり・花火大会の人出、ミシュラン評価…
- **壞**：台風接近、大雪、食材値上げ、冷蔵庫故障、コンロ故障、停電、水道工事、抜き打ちの衛生検査、
  食中毒の噂、近隣工事の騒音、万引き、ネズミ、従業員の急な欠勤、悪質な口コミ、火災報知器の誤作動…
- **中性**：商店街の清掃活動、祭りで通行止め、仕入れ先の変更…

**10 個事件可以靠設備把傷害減半**（監視器 → 万引き・ネズミ、滅火器 → コンロ故障、
消防設備 → 火災報知器、保全系統 → 台風、紅外線 → 侵入、商用冰箱 → 食材漲價・衛生検査…）。
設備在「従業員 → 設備・事件」購買；故障設備可以花錢修理。

### 設定（⚙ 設定 / 快捷鍵 O）

和舊版一樣有一個「環境設定」面板，兩個分頁：

**環境設定**
| 項目 | 內容 |
|---|---|
| 營業時間 | 開店／打烊滑桿（至少 2 小時，開店必須早於打烊）；營業中調整會即時反映，時數直接影響人件費與員工疲勞 |
| 音量 | マスター／音楽／効果音 三條滑桿（即時生效，並記在存檔與 localStorage） |
| 画質 | 解像度（自動／1×／1.5×／2×）、陰影開關、陰影精度（2048／1024／512）——變更立即生效 |
| カメラ・ゲーム | 視野角（30〜70°）、自動旋轉、開始速度 |

**存讀檔**
- **6 個槽位**：スロット 1〜5 ＋ オートセーブ，存於瀏覽器 localStorage。
- 每個槽位顯示**日期時間、地點、天數、所持金、星級、員工人數、人氣**。
- 按鈕：**ここに保存 / 読み込む / 上書き保存 / 削除**。
- **打烊結算時會自動存到「オートセーブ」**。
- 讀檔會**完整還原**：天數、現金、菜單、員工（含疲勞與心情）、任務、出餐口的菜、
  桌面髒污、洗手間髒污、進行中的事件與事件紀錄、設備與故障、**以及亂數狀態**
  （所以讀檔後的天氣與事件序列會與存檔當下一致），場景與員工 3D 模型也會重建。

### 地點主題

每個立地都有獨特的**室內配色**（牆面、地板、踢腳板材調）與**背景音樂調性**（陽音階／陰音階／都節／民謠），換地點時餐廳氛圍會跟著改變。

### 員工制服

「🏗 店舗 → 👕 制服」面板可依職種換制服：料理人 5 套（經典廚師、現代主廚、和食職人、披薩師傅、甜點師傅）、ホール 5 套（經典黑白、休閒丹寧、爵士酒館、偶像風、夏日輕裝）。
每一套都有色票預覽，按「全員に適用」一次換整個職種（3D 模型會即時重建），也可以在最下面的「個人ごと」清單單獨換某位員工。
（「従業員」面板的名冊裡也有同樣的個人下拉選單。）

### 門口的「にぎわい看板」（店內人數＋候位名單）

店門口立著一塊即時更新的看板（自發光面板，晚上也看得到）：

```
本日のにぎわい
空席あり  店内 6 名　（36 席 / 空き 30）
本日の来客 41 名
行列 4 組・待ち 8 分
 1. 2 名様  待ち 8 分  🐾 カップル
 2. 4 名様  待ち 3 分     家族連れ
ペット同伴席 4 卓（店内 0 組・本日 2 組）
```

客滿時變成紅色的「満席」、沒有候位時顯示「行列なし（すぐご案内できます）」。
同一份資料（`crowdInfo()`）也顯示在「📊 分析」面板最上面（含完整候位名單），頂部資訊條的「行列」欄位滑過去看得到最長等待時間。

### ペット同伴席（帶寵物的客人有專屬座位）

一樓靠門口與緣側的 **4 張桌子（共 12 席）是ペット同伴席**：桌邊鋪寵物墊、放水碗與飼料碗，並立一個「ペット可」小牌。

- 帶寵物的客人（家庭／情侶／銀髮族約 13%）**優先被帶到寵物席**，客滿才會坐普通桌（不會被擋在門外）。
- 沒帶寵物的客人**優先坐普通桌**，把寵物席留給需要的人。
- 入座後寵物會離開隊伍、走到桌邊的墊子上趴著（面向桌子）。
- 榻榻米上的矮桌是**盤坐**（座高只有坐墊高），不會再飄在半空中。

### 顧客多樣化

每組客人依類型有各自的髮型、服裝、配色；**家庭客、情侶、銀髮族約 13% 會帶寵物**（犬、猫、うさぎ、鳥）進店，寵物會跟在組旁邊移動。

### 擴建樓層（🏗 店舗 / 快捷鍵 E）

餐廳可從 1 樓擴建到 **3 樓**（2F ¥80 萬、3F ¥240 萬；一次跳兩層要付兩層的錢，面板會同時給「2F を増築」「一気に 3F まで」兩個按鈕）。
每層多 8 張四人桌（+32 席），**客人和服務生會真的走樓梯上下樓**（客人上樓入座、下樓離店；服務生上樓送菜／收桌後再回一樓），
可從預設機位（全館／1F 客席／1F 厨房／2F／3F／爐前）切換視角。
面板也會列出每一層的桌數、席數與寵物席數量。

> 之前的増築藏在「従業員 → 設備・事件」分頁裡，而且 `main.js` 忘了 import `setFloorCount`，
> 按下去只會噴 `ReferenceError`（等於根本不能用）。現在獨立成「🏗 店舗」面板並修好。

### 顧客從街上來、吃完回街上

客人不是憑空出現在門口，而是**從街道的一端（人行道東西兩側，隨機）走過來**，
先在店門前集合再進門；吃飽結帳後走出大門、**沿著人行道往街道另一頭走遠才消失**。
客滿時會排在**店外人行道上的候位列**（有候位繩、支柱與「行列」看板），隊伍越長排越遠，
排到定位的人會轉身面向店門。店外也有街燈、斑馬線、巴士站牌與自動販賣機。

### 看廚師做菜（🍳 調理を見る / 快捷鍵 K）

- 點畫面上的**料理人**（或按 <kbd>K</kbd>／底部「🍳 調理を見る」）→ 鏡頭拉近並**持續跟拍**他；動一下鏡頭就會放開。
- 廚師頭上會飄一個**調理標籤**：誰在煮、**菜名（日文＋中文）、還有幾品、以及進度條**。
- 一樓是**開放式厨房**：爐台、鍋子、流理台、作業台、冷蔵庫、牆上棚架、出餐口（附燈）都建出來了；
  有廚師在煮時**爐火會亮、蒸氣會冒**（一台爐子對一位廚師），廚師也會擺出**攪拌的 cook 姿勢**。
- 「📊 分析」面板最上面是**調理場の状況**：每位料理人現在煮什麼、幾 % 完成、出餐口上有什麼菜等多久。

### 顧客詳情與熱門菜單

點擊畫面上的客人可查看狀態、心情、點餐內容、**這張單現在煮到幾 %（誰在煮）**、寵物。「📊 分析」面板顯示今日点単ランキング（品項數、營收、占比）與客層分布。

### 番付（排行榜 / 🏆 快捷鍵 T）

「🏆 番付」面板有兩個分頁：

- **この店**：自店在全部 28 個地點中的名次、売上順位の目安、店史紀錄（營業日數、累計売上、最高日商、最多来客、最高利益）、
  **料理ランキング**（全期間的菜色排行）、**料理人ランキング**（調理品數）、**ホールランキング**（經手營收、帶位／配膳／會計／清掃次數）、
  **客層ランキング**、**時間帯別売上**（哪個時段最賺）。
- **全地点**：28 個地點的**平均日商排行**（依人潮 × 客單價 × 星級換算），自店那一列會highlight，
  並顯示自店的**地点順位**與**売上順位の目安**、以及「已贏過幾個地點的平均」。

累計資料存在 `state.ledger`（菜色／客層／時段／員工／各地點成績），會一起存進存檔（`SAVE_VERSION 3`）。

### 經營

- **立地（店址）**：28 個日本地點，各有租金、人潮、客層組成、客單價、天氣機率與**名物**。
  星級不足的地點會鎖住；搬遷要付搬遷費（資金不足會被拒絕）。
- **名物加成**：把當地名物放進菜單，來客最多 +28%、該道菜可多賣 12%。
- **顧客**：7 種客群（会社員／学生／観光客／家族連れ／カップル／ご年配／宴会），
  每組 1～6 人，各自有來店時段曲線與耐心值；沒位子會在店外**排隊**，有位子立刻補位。
- **打烊結算**：売上 − 食材費 − 家賃 − 水光熱費 − **人件費（時給 × 營業時數）** ＋ 事件收支 ＝ 當日利益。
- **日夜循環**：遊戲內時間驅動太陽角度、天空色盤、霧氣與室內提燈；日落後提燈與霓虹點亮。

## 專案結構

```
dream-restaurant-3d/
  index.html                 遊戲外殼（import map + HUD）
  styles/app.css             和風 UI（墨／藍／朱／生成り／金）
  vendor/
    three.module.js          three.js r160（本地化，離線可用）
    RoomEnvironment.js       PBR 環境反射用
  src/
    main.js                  啟動、主迴圈、輸入、日夜循環、測試掛鉤
    sim/game.js              核心模擬：時間、客流、顧客狀態機、員工任務系統、經濟、結算、名物
    sim/events.js            事件系統：隨機事件排程、持續效果、設備減免
    sim/save.js              存讀檔（localStorage，6 槽位，亂數狀態可序列化）
    scene/
      lighting.js            天空穹頂、太陽／月亮、環境反射、提燈、天氣
      controls.js            自製環繞攝影機（無 addon 依賴）
      restaurant.js          日式餐廳組裝（含多樓層、開放式厨房、爐火蒸氣、調理標籤、街道與候位動線）
      props.js               31 種程序化日式道具（純幾何＋CanvasTexture）
      characters.js          程序化人物（7 種客群 × 9 種姿勢，含骨架與 cook 攪拌動作）
    data/
      locations.js           28 個日本地點資料（各含 theme：配色與音樂調性）
      dishes.js              44 道日本料理資料
      staff.js               32 名員工名冊（18 ホール / 14 料理人，★1〜★5）
      uniforms.js            料理人 5 套／ホール 5 套制服
      events.js              34 個事件（好 12 / 壞 16 / 中性 6）
    ui/hud.js                HUD、面板（立地／菜單／従業員／分析／番付／店舗／顧客／設定）、結算畫面    audio/audio.js          程序化音訊引擎（BGM／SFX／環境音，含離線渲染驗證 API）
  tools/
    scene-test.html          場景／資料／模擬驗證頁（16 個段落、約 150 項檢查）
    run-scene-test.ps1       用無頭 Chrome 跑上面那頁並把結果印出來（UTF-8 安全）
    audio-test.html          音訊驗證頁（OfflineAudioContext 實際渲染）
    bgm-bisect.html          BGM 各聲部的二分測試（找出哪個合成器有問題時用）
    serve.mjs                零依賴靜態伺服器（預設 8081）
```

## 驗證

開 <http://127.0.0.1:8081/tools/scene-test.html>，會檢查：
- 資料集：28 地點（客層與天氣機率合計 100）、44 料理（價格維持成本 2.8～4.2 倍）
- 道具庫：31 種道具全部可建立、`makeProp` 無失敗
- 人物：可建立、骨架齊全、9 種姿勢可用（含 `carry`／`cook`）、單人 mesh 數 ≤ 60
- 場景：mesh 數、無 NaN 座標、房間外殼、桌子與座位數一致、**沒有道具退回佔位幾何**、
  一樓有調理場（爐台・出餐口・吧台）與調理標籤 sprite、候位動線存在
- 模擬：快轉 12 小時後有來客／有服務／營業額 > 0、現金與統計皆為有限數
- 員工與服務流程：開局 1 料理人 + 1 ホール、招募名單星級合格、雇用扣簽約金、不能解雇最後一位、
  六種任務（帶位／調理／配膳／お会計／片付け／トイレ清掃）都會被建立並完成、出餐口會出現菜也會被取走、
  人件費計入結算、沒位子會排隊且空位後補位、事件可觸發且效果生效、設備減免、設備購買與修理
- 設定與存讀檔：營業時間驗證（拒絕打烊早於開店、拒絕不足 2 小時）、畫質設定寫入、
  存檔 → 破壞現況 → 讀檔後日數／現金／地點／員工／亂數狀態／設定全部還原、
  讀檔後仍可繼續模擬、刪除存檔、6 個槽位、缺 `ledger` 的舊存檔也能補
- 座位朝向：36 個座位的面向與「桌心」的 cos 值 ≥ 0.94（椅子不會再側擺）
- 街道：客人從街道兩端出生、離店會走到人行道並沿街走遠才消失、桌子在門口才還回去、
  候位隊伍在店外人行道且彼此有間距並面向店門
- 樓層：2F／3F 費用（¥80 萬／¥240 萬，1→3 要付兩層）、不能減樓層、
  客人會上樓用餐、服務生會上樓送菜、樓層編號不越界
- 調理場：爐台在厨房範圍內、料理人進入「調理中」且進度會跑、菜色有名字、
  廚師站在爐前、使用 `cook` 姿勢
- 番付：店內菜色／料理人／ホール／客層／時段排行都有資料、店史紀錄寫入、
  全地點 28 筆且名次 1..28 不重複、自店被標記且名次在範圍內、存讀檔後一致
- にぎわい看板：資料欄位齊全、客滿時顯示候位名單（號碼／人數／等待時間）、店內人數與本日來客、
  場景看板會隨狀態重畫
- ペット同伴席：至少 2 張且都在一樓、帶寵物的客人優先坐寵物席、寵物席客滿時可坐普通桌、
  普通客人優先坐普通桌、今日帶寵物組數有統計、場景有寵物墊位置
- 渲染：draw calls、三角形數、白天與夜晚都能出圖

UI 互動另外用 `?uitest=1` 驗（會**真的按下按鈕**）：
「🏗 増築 2F」→ 樓層變 2、場景樓層群組變 2、廚房爐火仍在（`adoptFrom` 有把新場景接回來）、
「全員に適用」→ 該職種所有員工的 `uniformId` 都換掉、所有面板都能開、客人／員工 mesh 數與模擬一致。

用無頭 Chrome 一次跑完並取出結果（PowerShell 直接讀 dump 會把中文讀成亂碼，這支腳本幫你處理好）：

```powershell
powershell -NoProfile -File tools/run-scene-test.ps1 -Url http://127.0.0.1:8081
# 全部通過 → 印出 SCENE TEST: ALL PASSED 並以 exit code 0 結束；有 FAIL 會列出並回傳 1
```

### 音訊驗證

`tools/audio-test.html` 用 **OfflineAudioContext 實際渲染**來證明「真的會發出聲音」
（不需要使用者手勢，也不需要人耳判斷）：

| 網址 | 檢查內容 |
|---|---|
| `?t=sfx` | 14 種音效全部有訊號、沒有破音；引擎行為、立地→音階對應、模擬事件 |
| `?t=music&scale=yo` | BGM 陽音階 |
| `?t=music&scale=in` | BGM 陰音階 |
| `?t=music&scale=miyako` | BGM 都節 |
| `?t=music&scale=night` | BGM 夜晚版（速度較慢、較疏） |

> 兩個環境限制（實機不受影響）：
> 1. headless Chrome 對「同一頁第二個 OfflineAudioContext」會卡住 → 驗證拆成多次載入。
> 2. 軟體音訊渲染很慢（BGM 約 6 倍實時 CPU），而 `--virtual-time-budget` 太大時 Chrome 會在
>    渲染完成前就 dump DOM → **請用較小的 budget（例如 30000）**。
> 音效驗證為了塞進短渲染，14 個音效的取樣窗會重疊，峰值相加可能 >1.0（實機有 DynamicsCompressor
> 且同一音效 40ms 內不重複，不會破音），因此該項以 peak < 1.6 為門檻並把超過 1.0 的樣本數列為資訊。

**實機驗證（最直接）**：開 `/?audio=1&debug=1` 會直接啟用音訊並播放數個音效，
畫面左下的診斷資訊會顯示 `audio.enabled: true`、`contextState: "running"`、`musicPlaying: true`、
`voices > 0`（`voices` 是實際播放過的效果音數量）。

### 測試用網址參數

| 參數 | 說明 |
|---|---|
| `?loc=tokyo_shibuya` | 指定開局地點（id 見 `src/data/locations.js`） |
| `?hour=21` | 直接設定遊戲內時刻（測光影） |
| `?stars=5` | 直接設定星級 |
| `?speed=4` | 開局速度 |
| `?panel=locations` | 開局直接打開面板（locations／menu／staff／help） |
| `?stafftab=hire` | 員工面板直接開在指定分頁（roster／hire／shop） |
| `?stab=saves` | 設定面板直接開在指定分頁（config／saves） |
| `?loadslot=auto` | 啟動時直接讀取該槽位（測試完整讀檔流程） |
| `?shot=2` | 指定預設機位（0～6：全館／1F／客席／厨房／2F／3F／爐前） |
| `?cam=az,pol,dist,tx,ty,tz` | 直接指定機位（截圖驗證用） |
| `?cook=1` | 開場把鏡頭對到正在做菜的料理人（會自動跟上；可搭配 `?ff=`） |
| `?uitest=1` | 把所有面板渲染一遍並**實際按下増築／制服按鈕**，結果寫進頁面上的 `<pre id="uitest">`（無頭驗證用） |
| `?shoptab=uniform` | 開場直接開「店舗」面板的指定分頁（expand／uniform） |
| `?probe=x,z,r` | 列出 (x,z) 半徑 r 內的所有 mesh（材質、大小、位置）——找不到怪東西時用 |
| `?ff=120` | 載入後快轉 120 遊戲分鐘 |
| `?static=N` | 只渲染 N 幀後停止（無頭瀏覽器截圖用） |
| `?debug=1` | 在畫面左下顯示相機／draw call／mesh 數等診斷資訊 |

> 無頭截圖小抄：`chrome --headless=new --screenshot=out.png --window-size=1280,800 "http://127.0.0.1:8081/?cook=1&ff=250&static=40"`
> （`?static=N` 會把最後一帧轉成 `<img>` 疊在畫面上，避免 rAF 停止後截到黑畫面。）

## 美術與效能

- **材質**：全部 `MeshStandardMaterial` / `MeshPhysicalMaterial`（PBR），
  貼圖一律用程式產生的 `CanvasTexture`（木紋、榻榻米編織、土壁、和紙、金箔、陶瓷釉、竹節…），
  **不使用任何外部圖檔**。
- **光線**：DirectionalLight（太陽／月亮，2048 陰影圖 + PCFSoft）＋ HemisphereLight 補光
  ＋ PMREM 環境反射 ＋ 5 盞室內點光（提燈／作業燈）。
- **接地感**：每個傢俱／人物腳下都有程序化接觸陰影貼片（AO blob），任何時刻都成立。
- **參考數字**：約 1,300 個 mesh、12 萬～19 萬三角形、1,200～1,900 draw calls
  （一樓含開放式厨房與街景；截圖見 `shots/`）。
