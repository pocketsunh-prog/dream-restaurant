# 夢幻西餐廳 3D ─ 日本編 / Dream Restaurant 3D

以 **three.js** 重製的《夢幻西餐廳》3D 版本，舞台移到**日本**，收錄 **28 個日本知名商圈／溫泉地／市場**，
日式風格餐廳（土壁、木地板、榻榻米座敷、障子、暖簾、提燈、行燈、招財貓、酒樽…），
PBR 材質 + 即時陰影 + ACES 色調映射 + 日夜循環。

本專案與 2D 版（上層目錄）**完全分離**，可獨立執行。

---

## 快速開始

```bash
cd dream-restaurant-3d

# 方式 A：用本專案附的伺服器（預設 8081）
node tools/serve.mjs
# → 瀏覽器開 http://127.0.0.1:8081/

# 方式 B：用上層 2D 專案的伺服器（8080）
cd .. && node tools/serve.mjs
# → 瀏覽器開 http://127.0.0.1:8080/dream-restaurant-3d/
```

> ⚠️ 一定要用 HTTP 伺服器開啟，不能用 `file://` 直接開檔：本專案用 ES module
> 與 import map（`three` → `vendor/three.module.js`），`file://` 會被 CORS 擋下。

**離線可用**：three.js（r160）已經放在 `vendor/`，執行時不需要任何網路連線。

## 音訊（程序化合成，無任何音檔）

全部的音樂與音效都是**即時用 Web Audio 合成**，專案裡沒有任何 `.mp3` / `.wav`。

- **BGM**：以日本音階隨機漫步產生旋律（箏／koto 撥弦：三角波＋兩個泛音），
  加上尺八風的氣息長音（兩支微失諧正弦＋帶通噪音）與太鼓脈動（低頻下滑音＋低通噪音）。
  - 音階：`yo`（陽音階，明亮）／`in`・`miyako`（陰音階・都節，物悲）／`minyo`（民謠）／`ryo`（呂）
  - **依立地類型選音階**：繁華街→陽音階、高級地段→陰音階、溫泉・古街→都節、市場→民謠
  - **依晝夜與時段改變**：夜晚速度放慢、音更疏、太鼓更輕；午間尖峰速度加快、音更密
- **SFX（14 種）**：`door` 引き戸＋門口鈴、`seat` 入座、`order` 點餐、`serve` 上菜、
  `eat` 餐具、`pay` 收銀＋零錢、`angry` 不滿低鳴、`happy` 滿意三音、`settle` 打烊鈴、
  `starup` 升級、`error`、`clink` 杯盤、`whoosh` 搬遷、`click` 按鈕
- **環境音**：店內人聲（帶通噪音，隨在店人數變化）、廚房聲（隨使用中的桌數）、雨聲（下雨時）
- **混音**：master → DynamicsCompressor → 輸出；music／sfx／ambience 三條匯流排可各自調音量；
  同一音效 40ms 內不重複觸發，避免大量顧客同時進店造成破音。

模擬層只負責產生事件（`door` / `seat` / `order` / `serve` / `pay` / `angry`），
呈現層用 `drainEvents(state)` 取用並決定要播什麼，兩邊完全解耦。

## 玩法

### 員工與服務流程（核心）

餐廳的營運是一條**任務驅動**的產線：模擬層只產生「任務」，員工自己認領並走過去執行。

```
客人進店 ──有位子──▶ 保留桌位 ──▶【服務生：帶位 seat】──▶ 入座 ──▶ 點餐
   │                                      │
   └──沒位子──▶ 店外排隊（等太久生气離開）  ▼
                                  【廚師：調理 cook】──▶ 菜放上出餐口（畫面上會出現碗盤）
                                            │
                                            ▼
                                  【服務生：配膳 deliver】──▶ 客人開始用餐
                                            │
                                            ▼
                                  用餐結束 ─▶【服務生：お会計 collect】──▶ 結帳、桌面變髒（出現碗盤堆）
                                            │
                                            ▼
                                  【服務生：片付け cleanTable】──▶ 桌子可再帶客
                                  洗手間髒了 ─▶【服務生：トイレ清掃 cleanRestroom】
```

| 任務 | 角色 | 內容 |
|---|---|---|
| `seat` ご案内 | ホール | 到門口把客人帶到桌位（客人會跟著走到座位） |
| `cook` 調理 | 料理人 | 走到爐台煮菜，煮好**把菜放上出餐口** |
| `deliver` 配膳 | ホール | 到出餐口**取菜**（畫面上會端著盤子）再送到桌邊 |
| `collect` お会計 | ホール | 客人用完餐後到桌邊**埋單**（手藝好的服務生小費較高） |
| `cleanTable` 片付け | ホール | 收拾桌面，桌子才能再帶客 |
| `cleanRestroom` トイレ清掃 | ホール | 洗手間髒污過高時自動產生 |

- 任務有**優先度**（埋單 92 ＞ 送菜 86 ＞ 帶位 78 ＞ 收拾 58 ＞ 掃廁所 46），員工挑最要緊的先做。
- 作業時間與走路速度取決於員工的 **skill／speed**，**疲勞**會拖慢一切。
- **人手不足的後果**：沒有料理人 → 客人等不到菜；沒有ホール → 客人等不到帶位／送菜／埋單，
  撐過耐心值就生气離開（評價下降）。客人也可能自己跑去櫃台結帳，但小費減半。
- 員工上限 10 人，至少要留 1 位料理人與 1 位ホール。

### 員工招聘（32 人名冊）

「従業員」面板有三個分頁：

1. **現有員工**：姓名／年齡／時給／擔當／**現在正在做什麼**（待機・ご案内・配膳…）＋
   速度・手腕・体力・疲労四條能力條＋特質標籤，可解雇（資遣費＝時給 ×4）。
2. **招募**：依星級出現的應徵者（★1 8 人／★2 8 人／★3 7 人／★4 5 人／★5 4 人），
   有簽約金（＝時給 ×2）、能力、專長（料理人 10 種料理類別／ホール 5 種服務專長）與 12 種個性；
   雇用後立刻上工（會出現在店裡）。
3. **設備・事件**：購買設備、修理故障設備、查看進行中事件與事件紀錄。

### 事件（34 種）

營業中每 90～210 分鐘擲一次隨機事件（好 12／壞 16／中性 6），
會依**星級、天氣、立地類型**篩選，效果可持續數十分鐘，進行中的事件顯示在畫面右上角：

- **好**：テレビ取材、有名ブロガー来店、SNSでバズる、忘年会の予約、桜まつり・花火大会の人出、ミシュラン評価…
- **壞**：台風接近、大雪、食材値上げ、冷蔵庫故障、コンロ故障、停電、水道工事、抜き打ちの衛生検査、
  食中毒の噂、近隣工事の騒音、万引き、ネズミ、従業員の急な欠勤、悪質な口コミ、火災報知器の誤作動…
- **中性**：商店街の清掃活動、祭りで通行止め、仕入れ先の変更…

**10 個事件可以靠設備把傷害減半**（監視器 → 万引き・ネズミ、滅火器 → コンロ故障、
消防設備 → 火災報知器、保全系統 → 台風、紅外線 → 侵入、商用冰箱 → 食材漲價・衛生検査…）。
設備在「従業員 → 設備・事件」購買；故障設備可以花錢修理。

### 設定（⚙ 設定 / 快捷鍵 O）

和舊版一樣有一個「環境設定」面板，兩個分頁：

**環境設定**
| 項目 | 內容 |
|---|---|
| 營業時間 | 開店／打烊滑桿（至少 2 小時，開店必須早於打烊）；營業中調整會即時反映，時數直接影響人件費與員工疲勞 |
| 音量 | マスター／音楽／効果音 三條滑桿（即時生效，並記在存檔與 localStorage） |
| 画質 | 解像度（自動／1×／1.5×／2×）、陰影開關、陰影精度（2048／1024／512）——變更立即生效 |
| カメラ・ゲーム | 視野角（30〜70°）、自動旋轉、開始速度 |

**存讀檔**
- **6 個槽位**：スロット 1〜5 ＋ オートセーブ，存於瀏覽器 localStorage。
- 每個槽位顯示**日期時間、地點、天數、所持金、星級、員工人數、人氣**。
- 按鈕：**ここに保存 / 読み込む / 上書き保存 / 削除**。
- **打烊結算時會自動存到「オートセーブ」**。
- 讀檔會**完整還原**：天數、現金、菜單、員工（含疲勞與心情）、任務、出餐口的菜、
  桌面髒污、洗手間髒污、進行中的事件與事件紀錄、設備與故障、**以及亂數狀態**
  （所以讀檔後的天氣與事件序列會與存檔當下一致），場景與員工 3D 模型也會重建。

### 經營

- **立地（店址）**：28 個日本地點，各有租金、人潮、客層組成、客單價、天氣機率與**名物**。
  星級不足的地點會鎖住；搬遷要付搬遷費（資金不足會被拒絕）。
- **名物加成**：把當地名物放進菜單，來客最多 +28%、該道菜可多賣 12%。
- **顧客**：7 種客群（会社員／学生／観光客／家族連れ／カップル／ご年配／宴会），
  每組 1～6 人，各自有來店時段曲線與耐心值；沒位子會在店外**排隊**，有位子立刻補位。
- **打烊結算**：売上 − 食材費 − 家賃 − 水光熱費 − **人件費（時給 × 營業時數）** ＋ 事件收支 ＝ 當日利益。
- **日夜循環**：遊戲內時間驅動太陽角度、天空色盤、霧氣與室內提燈；日落後提燈與霓虹點亮。

### 音訊驗證

`tools/audio-test.html` 用 **OfflineAudioContext 實際渲染**來證明「真的會發出聲音」
（不需要使用者手勢，也不需要人耳判斷）：

| 網址 | 檢查內容 |
|---|---|
| `?t=sfx` | 14 種音效全部有訊號、沒有破音；引擎行為、立地→音階對應、模擬事件 |
| `?t=music&scale=yo` | BGM 陽音階 |
| `?t=music&scale=in` | BGM 陰音階 |
| `?t=music&scale=miyako` | BGM 都節 |
| `?t=music&scale=night` | BGM 夜晚版（速度較慢、較疏） |

> 兩個環境限制（實機不受影響）：
> 1. headless Chrome 對「同一頁第二個 OfflineAudioContext」會卡住 → 驗證拆成多次載入。
> 2. 軟體音訊渲染很慢（BGM 約 6 倍實時 CPU），而 `--virtual-time-budget` 太大時 Chrome 會在
>    渲染完成前就 dump DOM → **請用較小的 budget（例如 30000）**。
> 音效驗證為了塞進短渲染，14 個音效的取樣窗會重疊，峰值相加可能 >1.0（實機有 DynamicsCompressor
> 且同一音效 40ms 內不重複，不會破音），因此該項以 peak < 1.6 為門檻並把超過 1.0 的樣本數列為資訊。

**實機驗證（最直接）**：開 `/?audio=1&debug=1` 會直接啟用音訊並播放數個音效，
畫面左下的診斷資訊會顯示 `audio.enabled: true`、`contextState: "running"`、`musicPlaying: true`、
`voices > 0`（`voices` 是實際播放過的效果音數量）。

## 美術與效能

- **材質**：全部 `MeshStandardMaterial` / `MeshPhysicalMaterial`（PBR），
  貼圖一律用程式產生的 `CanvasTexture`（木紋、榻榻米編織、土壁、和紙、金箔、陶瓷釉、竹節…），
  **不使用任何外部圖檔**。
- **光線**：DirectionalLight（太陽／月亮，2048 陰影圖 + PCFSoft）＋ HemisphereLight 補光
  ＋ PMREM 環境反射 ＋ 5 盞室內點光（提燈／作業燈）。
- **接地感**：每個傢俱／人物腳下都有程序化接觸陰影貼片（AO blob），任何時刻都成立。
- **參考數字**：約 1,400 個 mesh、13 萬～16 萬三角形、1,200～1,400 draw calls。
