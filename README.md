# 夢幻西餐廳 — 復刻版

一款以原生 HTML / CSS / ES Modules 實作、**零外部依賴**的餐廳經營模擬遊戲，
復刻 1998 年由華藝國際代理的台灣經典《夢幻西餐廳》系列（藍本為《夢幻西餐廳：決戰全台灣》）。

從中壢新明夜市的一星小店開始，擺桌椅、編菜單、叫貨、請員工，
一路經營到高雄新堀江，挑戰五星與年度大獎 **The Greatest Restaurant of the Year**。

---

## 快速開始

```powershell
cd D:\dev\dream-restaurant
node tools/serve.mjs        # 或 pnpm start
# 瀏覽器開啟 http://127.0.0.1:8080/
```

需要 Node 18+（只用來跑本機靜態伺服器與測試）。遊戲本身是純前端，沒有任何 build step。

**模擬煙霧測試**（無 DOM，驗證 7～60 天的營運不變式）：

```powershell
node tests/smoke.mjs 30     # 跑 30 個遊戲日
```

**除錯用網址參數**（自動化測試／截圖用）：

| 參數 | 效果 |
|---|---|
| `?autostart=1` | 跳過開場畫面與教學 |
| `?open=1` | 直接開始營業 |
| `?ff=250` | 載入後快轉 250 遊戲分鐘 |
| `?days=11` | 直接跑完 11 個完整營業日（含週結算） |
| `?panel=menu` | 開啟指定面板（menu/staff/build/report/settings/system） |
| `?show=settle` | 直接顯示事件畫面（settle/starup/award/gameover） |
| `?loc=keelung_miaokou` | 搬到指定地點（跳過星級限制） |

`tools/zoom.html?src=/路徑.png&x=..&y=..&w=..&h=..&s=3` 可以把任何遊戲截圖局部放大檢視（美術檢查用）。

## 怎麼玩

### 一、開店前（準備階段）

1. **裝潢**：買桌椅、留走道。動線是這款遊戲的核心 ——
   座位離廚房出餐口越遠，一個服務生能負責的桌數越少，客人也等越久。
2. **菜單**：上架料理並調整 **售價 / 材料等級 / 味道濃淡 / 份量 / 調理時間**。
   - 調理時間太短 → 客人覺得是微波食品，評價重扣（原作設定）。
   - 售價高於顧客心中的合理價太多 → 覺得被坑。
3. **進貨**：叫貨後 30 分鐘到貨。賣完 = 客人點不到餐 = 生氣走人。
4. **員工**：雇用廚師與服務生，指派職務（帶位／點餐／送餐／收桌／**清掃廁所**／櫃檯結帳），排班要涵蓋營業時間。
5. 按 **▶ 開始營業**。

### 二、營業中

- 即時模擬：客人上門 → 候位 → 帶位 → 點餐 → 廚房料理 → 送餐 → 用餐 → 結帳 → 收桌。
- 可以即時調售價、叫貨、調空調溫度、換音樂、指派清掃。
- **點畫面下方走動的路人**可以拉客（人氣加成，上限 +30%，半衰期 20 分鐘）。
- 左下角「餐廳小提示」會即時告警（太冷太熱、有人在等、廁所髒、庫存不足、設備故障…）。

### 三、打烊後

- 當日營業報告（自動存檔）。
- **每週日 22:00**：雜誌五榜結算（口味／服務／裝潢／價格／人氣）＋ 星級評定。
- **每週一**：社區獎金 NT$ 200,000 入帳。

### 四、評價與升星

評價分成 **社區** 與 **區外** 兩桶（0–500，起始 350），兩桶都要達標才能升星：

| 星級 | 社區 | 區外 | 額外條件 |
|---|---|---|---|
| ★1 | 350 | 350 | 開業 |
| ★2 | 380 | 360 | 營業滿 7 天 |
| ★3 | 410 | 385 | 週排名前 8 |
| ★4 | 435 | 410 | 週排名前 3 且曾拿第一 |
| ★5 | 460 | 435 | 連兩週雜誌總排名第一 |
| 年度大獎 | — | — | 五星後再撐 120 天且年度排名第一 |

- 連續 3 週低於門檻會掉星。
- **搬遷地點會讓區外評價大幅下滑**（原作實測現象），而且裝潢全部清空要重排。

### 五、六個台灣地點（依星級解鎖）

中壢新明夜市 ★1 → 基隆廟口 ★2 → 台北南陽街 ★3 → 台中中華路 ★4 → 台南東帝士廣場 ★4 → 高雄新堀江 ★5

每個地點的租金、基礎客流、顧客組成、口味偏好、天氣分布、格局（大門位置／廚房大小／隔間／廁所方位）與窗外街景都不同。

## 攻略要點

- **前期**：漢堡牛肉餅是無敵招牌（原作設定），先靠它與蛋包飯、紅茶把現金流做起來。
- **動線**：出餐口旁的桌子留給翻桌率最高的客人；服務生走不到的位置等於沒有座位。
- **廚房**：一位廚師同時只能顧 3 個鍋子，客人一多就要加廚師，否則「等餐」直接吃掉評價。
- **清潔**：務必指派至少一位服務生「清掃廁所」與「清掃店內」，髒污會持續扣心情。
- **設備**：監視器、紅外線、滅火器、消防設備、保全主機對應不同的突發事件，買了損失大幅下降。
- **廚房設備**：在「系統 → 廚房設備」升級爐具（加速煮菜）、冰箱（減少折損）、流理台（增加廚師鍋數）。
- **桌子配椅子**：買桌子會自動配滿對應數量的椅子（2/4/6 人桌分別配 2/4/6 張），不用再單獨買椅子。
- **自動排班**：在「員工 → 排班」按「⚡ 自動排班」把全部員工排成 8 小時一班、錯開覆蓋全日。
- **自動重建**：在「系統」按「🏗 自動重建頂級餐廳（NT$ 1）」一鍵重置為頂級配置。
- **配色**：在「環境 → 配色」自訂牆面與地板顏色（8 組預設 + 自訂 color picker），改用扎實純色繪製。
- **材料等級**：提升材料等級是「口味」分數的主要來源，也是避免食物中毒的關鍵（平均等級 < 42 才會出事）。
- **價格**：售價 ≈ 材料成本的 7～10 倍是甜蜜點；低於成本 1.2 倍會賠錢。

## 專案結構

```
index.html              遊戲外殼
styles/                 90 年代米黃色視窗設計系統
src/
  main.js               主迴圈、HUD、工具列、畫布互動
  core/                 亂數、狀態、store/reducer、存檔、音效、數值平衡
  data/                 料理 68、員工 28、地點 6、傢俱 36、事件 32
  sim/                  模擬：顧客 AI、員工 AI、動線 A*、經濟、評價、雜誌、事件
  render/               程序化像素繪圖（等角平面、人物、傢俱、街景、天氣）
  ui/                   共用元件、視窗管理員、六個管理面板、結算畫面
tests/smoke.mjs         無 DOM 模擬煙霧測試
tools/serve.mjs         零依賴靜態伺服器
tools/ui-test.html      傢俱操作端到端 UI 測試（瀏覽器開 /tools/ui-test.html）
tools/zoom.html         截圖局部放大檢視（美術檢查）
```

## 操作

| 操作 | 說明 |
|---|---|
| `~` | 密技控制台（money／star／unlock／weather／open／close／clear／help） |
| 底部工具列 | 開啟 菜單 / 員工 / 裝潢 / 報表 / 環境 / 系統 面板 |
| **點畫面上的傢俱** | 選取它，並在上方跳出工具列：**移動 / 旋轉 / 更換 / 拆除** |
| **直接拖曳傢俱** | 按住拖到新位置放開就能搬家（位置不合法會擋下來並說明原因） |
| `R` | 旋轉選取的傢俱（椅子會自動面向相鄰的桌子） |
| `M` | 移動選取的傢俱（再點一下平面圖決定位置） |
| `Delete` | 拆除選取的傢俱（退回 50%） |
| `Esc` | 取消選取／取消待擺放 |
| 點畫面上的路人 | 拉客（人氣加成） |
| 點客人 | 顯示他的狀態、心情、等待時間與點的菜 |
| `1x / 2x / 4x / ❚❚` | 遊戲速度（暫停／正常／兩倍／四倍） |
| 面板標題列 | 可拖曳移動視窗 |

> 買錯傢俱不用整間拆掉重來：點它 → **更換**，就能用同類傢俱就地換掉（舊品退 50%、只收差額），
> 位置與朝向都保留，同桌的客人也不會受到影響。

## 已知限制

- 存檔放在瀏覽器 `localStorage`（5 個手動槽 + 每日自動存檔），換瀏覽器不會帶著走。
- 音效與 BGM 由 WebAudio 程序化合成，需要先有一次使用者互動（瀏覽器自動播放政策）。
- 沒有分店系統 —— 與原作相同，只能舉家搬遷。
